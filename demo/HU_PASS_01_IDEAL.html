ÉpicaEP-001: Autenticación y Control de Acceso PROPUESTO

Descripción Como usuario registrado del sistema
Quiero restablecer mi contraseña mediante un enlace enviado a mi correo
Para recuperar el acceso al sistema cuando olvido mis credenciales
Usuarios / RolesUsuario registrado (cuenta activa)
Reglas de Negocio BR1: Al solicitar la recuperación con un correo, el sistema envía un enlace de restablecimiento con token único e impredecible. La respuesta en pantalla es genérica e idéntica exista o no la cuenta (previene enumeración de usuarios).
BR2: El enlace expira a los 30 minutos PROPUESTO de generado y es de un solo uso: tras utilizarse o expirar queda invalidado.
BR3: La nueva contraseña debe tener mínimo 8 caracteres, incluyendo mayúscula, minúscula y número PROPUESTO.
BR4: Toda solicitud y cambio de contraseña (exitoso o fallido) queda registrado en el log de auditoría con fecha/hora, correo, IP y resultado.
Precondiciones • El usuario debe estar registrado con cuenta activa y correo verificado
• El servicio de envío de correos debe estar operativo
• La base de datos de usuarios debe estar disponible
Dependencias • Servicio de correo/notificaciones del sistema
• API de autenticación del backend
• Servicio de auditoría/logging

Escenarios de Prueba (Criterios de Aceptación)
E1: Solicitud exitosa de restablecimiento AGREGADO
DADO que el usuario está registrado con una cuenta activa y correo válido
CUANDO ingresa su correo en "Olvidé mi contraseña" y presiona Enviar
ENTONCES el sistema envía un correo con un enlace de token único y muestra "Si el correo está registrado, recibirá un enlace de recuperación"
Y el evento queda registrado en el log de auditoría
E2: Correo no registrado — anti-enumeración AGREGADO · OWASP A07
DADO que el correo ingresado NO corresponde a ningún usuario registrado
CUANDO solicita el restablecimiento
ENTONCES el sistema muestra exactamente el mismo mensaje genérico y NO envía ningún correo
Y no revela la existencia de la cuenta ni por mensaje ni por tiempo de respuesta
E3: Restablecimiento exitoso dentro de la vigencia AGREGADO
DADO que el usuario recibió un enlace generado hace menos de 30 minutos
CUANDO accede al enlace y define una nueva contraseña que cumple la política
ENTONCES el sistema actualiza la contraseña, invalida el token y muestra "Su contraseña fue restablecida correctamente"
Y permite iniciar sesión con la nueva contraseña
E4: Enlace expirado AGREGADO · OWASP A07
DADO que el enlace fue generado hace más de 30 minutos
CUANDO el usuario accede al enlace
ENTONCES el sistema muestra "El enlace ha expirado. Solicite uno nuevo" y no permite definir contraseña
E5: Frontera de expiración AGREGADO · Valores Límite
DADO que existen enlaces generados hace 29:59 y hace 30:01
CUANDO el usuario accede a cada uno
ENTONCES el de 29:59 permite restablecer y el de 30:01 es rechazado como expirado
E6: Contraseña válida según política AGREGADO
DADO que el usuario accedió con un enlace vigente
CUANDO define una contraseña de mínimo 8 caracteres con mayúscula, minúscula y número
ENTONCES el sistema la acepta y completa el restablecimiento
E7: Contraseña débil rechazada AGREGADO
DADO que el usuario accedió con un enlace vigente
CUANDO define una contraseña que incumple la política (7 caracteres, sin mayúscula, sin número o vacía)
ENTONCES el sistema la rechaza con "La contraseña no cumple los requisitos: mínimo 8 caracteres, mayúscula, minúscula y número" y no la actualiza
E8: Token de un solo uso AGREGADO · OWASP A07
DADO que el usuario ya restableció su contraseña usando el enlace
CUANDO intenta reutilizar el mismo enlace
ENTONCES el sistema lo rechaza con "El enlace ya fue utilizado" y no permite un segundo restablecimiento
E9: Auditoría de solicitudes y cambios AGREGADO · OWASP A09
DADO que ocurre cualquier solicitud o cambio de contraseña (exitoso o fallido)
CUANDO el evento se procesa
ENTONCES queda registrado en el log de auditoría con fecha/hora, correo, IP de origen y resultado
